# 每日自动推送执行规范

建议每天在 `Asia/Shanghai` 时区固定时间执行一次（推荐上午 10:00~12:00）。

## 自动化输入

- 日期：`YYYY-MM-DD`
- 每日词条数：**5~10 条**
- 允许领域：通用、物理、哲学、心理学、工程测量
- 允许难度：低、中、高
- 固定词库包：每日热词

## 信息来源

优先从以下渠道采集过去 24 小时内最热的新闻和话题：

- **微博热搜**：社会热点、娱乐事件、公共讨论
- **知乎热榜**：深度话题、科技讨论、社会议题
- **科技媒体**：IT之家、钛媒体、36氪、Edge AI Daily、网易科技
- **财经早报**：证券时报、第一财经、新浪财经、腾讯新闻
- **综合新闻**：四川观察、新华社、澎湃新闻

## 自动化必须完成的动作

1. **采集热点**：从上述来源获取过去 24 小时内最热的新闻和话题。
2. **提炼关键词**：从热点中提炼 5~10 个最核心、最具教育价值的关键词（优先选择背后有可解释概念的词，而非纯娱乐八卦）。
3. **生成词条**：按 `daily.template.json` 格式为每个词生成完整内容：
   - `simpleExplanation`：一句小学生也能听懂的话
   - `lifeAnalogy`：一个具体、熟悉的生活场景类比
   - `practicalApplication`：在日常生活或工作中的实际用途
   - `commonMisconception`：大家最容易搞错的一个地方
   - `definition`：准确完整的中文定义（含热点时间背景）
   - `appear`：**标明热词在热点中出现的具体时间**（如“2026年8月19日（……，央视报道）”），满足“标注热词出现的时间”要求
   - `sourceUrl`：**必须附带词汇出处/原文链接**（菜鸟教程词包风格）
4. 按 `YYYYMMDDNN` 生成整数 ID，`NN` 从 `01` 开始。
5. 输出符合 `schema/words.schema.json` 的 JSON 数组。
6. 将数组同时写入：
   - `daily_hotwords/words.json`
   - `daily_hotwords/archive/YYYY/MM/YYYY-MM-DD.json`
   - `daily_hotwords/archive/YYYY/MM/YYYY-MM-DD.explain.md`（详细解释文档，包含来源、时间和出处链接）
7. 同步更新 `daily_hotwords/library.json`：当日词条替换该日历史记录，保留往日词条。
8. 更新 `daily_hotwords/manifest.json`：
   - `updatedAt`
   - `sourceFile`
   - `wordCount`
9. **校验（推送前必做，防乱码）**：确认 JSON 为 UTF-8、**无 BOM**、**无 U+FFFD 替换符**（这两项即“乱码”判定标准）、可解析、ID 无重复且为 `YYYYMMDDNN` 格式、字段枚举/长度合法、`sourceUrl` 不为空且当日 10 条互不相同、definition 含 35~100 个汉字、`archive` 与 `words.json` 内容一致。
   - 用 Python 脚本逐字段校验（托管 Python + 环境变量 `PYTHONIOENCODING=utf-8` 写文件，杜绝中文乱码）；**本项目无 dart 工具，切勿运行 `dart` 命令。**
   - `appear`（出现时间）与 `sourceUrl`（出处链接）已写入 `schema/words.schema.json`，可用 JSON Schema 直接校验，二者当日须互不相同且非空。
   - 所有 `sourceUrl` 必须真实有效、指向热点原文或权威来源（菜鸟教程词包风格“出处链接”），且同一天 10 条互不相同。
10. 校验格式无误后，Git 提交信息固定为 `hotwords: publish YYYY-MM-DD`，并推送到远程仓库。

## 内容质量要求

- 不直接复制新闻标题；选取标题背后的可解释概念。
- 定义控制在 35～100 个汉字，避免循环定义。
- 四段详解使用完整中文句子，内容具体，避免四个字段只是重复标准定义。
- 拼音使用带声调的拉丁字母。
- 同一天避免所有词条属于同一狭窄主题，尽量覆盖科技、财经、社会、科学、健康等多类别。
- **sourceUrl 必须真实有效**，指向热点事件的原始报道或权威信息来源。
- 不删除历史归档，不修改已经发布的旧归档；勘误另作提交说明。

## 失败处理

- 任一步验证失败时，不覆盖 `words.json`，不提交 Git。
- GitHub 推送失败时保留本地归档，下一次运行先重试推送。
- 当天归档已存在且词条数>=5时停止执行，避免重复生成与覆盖。
